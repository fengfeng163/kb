## CMDBと構成アイテム
![[Pasted image 20260624080442.png]]

Configuration アプリケーションには、ハードウェアやその他の構成アイテム用のモジュールなど、CMDB のコア機能が用意されています。この機能は、ベースインストールで有効になる CMDB プラグインに含まれています。

CMDB では、会社に存在する CI を特定、制御、管理、および検証することによって、会社のインフラストラクチャの論理モデルを使用できます。  

CI は、サービスを提供するために管理する必要がある、すべてのコンポーネントです。通常、CI には、ビジネスアプリケーションおよびハードウェアなど、サービスとその基本的なコンポーネントが含まれます。ただし、「サービス」という単語は進化し続けていて、しばしば乱用されているので注意してください。このため、「サービス」について言及する場合は話が複雑になることがあります。  

3 つの重要な CMDB テーブルは、Base Configuration Item [cmdb]、Configuration Item [cmdb_ci] (CI データを含む)、CI Relationship [cmdb_rel_ci] (CI 関係性データを含む) です。

ServiceNow の CMDB は、静的リストとは異なり、プラットフォーム内の CI だけでなく、それらのアイテム間の関係性も追跡します。時間とともに CI の数が増加するにつれて、CMDB のパフォーマンスと健全性が影響を受ける可能性があります。CMDB データマネージャーツールを使用して CI ポリシーを作成、公開、管理すると、CMDB を効率的に運用可能な状態で維持するのに役立ちます。  

詳細については、ServiceNow 製品ドキュメント『CMDB データマネージャー』を参照してください。

## ITSMプロセスでのCMDBの使用

![[Pasted image 20260624080735.png]]

CMDB は、情報システムのすべてのコンポーネントに関連する情報のリポジトリです。IT 分野では CMDB と同様のリポジトリが長年使用されてきましたが、CMDB の起源は ITIL (Information Technology Infrastructure Library) にあります。CMDB は、効果的で効率的なビジネスプロセスと IT サービスマネジメントを実現するために、どのようなシステムコンポーネントが必要かを監視して検出するのに役立ちます。  

すべてのサービスマネジメントプロセスは CMDB に関係があり、CMDB を必要としています。たとえば、問題に関する電話連絡があり、根本原因分析を実行する必要がある場合、効果的なトラブルシューティングのための情報が CMDB から得られます。  

![[Pasted image 20260624081008.png]]

**メリット** :  
インシデントの多くは変更の失敗が原因です。正確で最新状態の CMDB は、次のように IT チームを支援します。  
- 変更の失敗と関連インシデントを特定できます。  
- 提案される変更の影響を簡単に分析でき、停止時間を削減または排除できます。  
- 特定の CI に関する問題の傾向を評価できます。  
- CI やサービスデリバリに影響するインシデントを効率的に管理できます。

## 構成アイテム : 依存関係ビュー
Dependency Views (依存関係ビュー) は、構成アイテム間の関係を視覚化するインタラクティブなグラフィカルインターフェイスを提供します。

![[Pasted image 20260624081437.png]]

ServiceNow のサービス (アプリケーションサービスまたはビジネスサービス) は、IT インフラストラクチャによってサポートされている作業または商品です。たとえば、メールサービスを従業員に提供するには、メールサーバー、Web サーバー、ユーザーアカウントの設定作業などのサービスが必要になる場合があります。依存関係ビューは、インフラストラクチャにおける CI 間の関係を確認するのに役立ちます。  

表示している例では、ビジネスサービス (Bond Trading と SAP Payroll) がデータベースへのアクセスを必要としていて、さらに nyc oracle クラスターも必要なことが確認できます。このマップ内の何かが (機能停止、システム変更などにより) 利用できなくなると、SAP Payroll などのビジネスサービスは影響を受ける可能性があります。  

Dependency Views マップには、マップのルート CI またはルートノードと呼ばれる開始点が 1 つあります。ルート CI は、注意を引き付けるためにパルスエフェクトを使用した濃い色の枠で囲まれています。マップには、ルート CI の上流と下流のどちらの依存関係も表示できます。デフォルトで、Dependency Views マップには上流と下流のどちらの関係についても 3 つのレベルが表示されます。管理者は、表示されるレベル数を設定できます。マップを見やすくするために、クラスターを折りたたんだり、展開したりすることができます。デフォルトでは、クラスターは折りたたまれています。  

Dependency Views マップでは、マップインジケーターが CI にアクティブな保留中の問題があるかどうかを示します。CI に接続されているタスクを調べて、詳細を確認することができます。別のフォームからマップに戻ると、デフォルトのフィルターとレイアウト設定を使用して、最後に表示していたマップが復元されます。CI レコードまたは CI を特定するタスクレコード上のマップをクリックすると、マップが開きます。  

マップ内の多くの関係が、検出プロセスを通して作成されます。マップ内の CI の関係を作成、定義、削除することもできます。別の観点からマップを表示したり、構成アイテムに関連する固有のレコードを開いたりすることもできます。マップは自動的に更新され、CMDB に対する変更が反映されます。

## CIクラスマネージャー
![[Pasted image 20260624081818.png]]
システム管理者は定期的には CMDB を操作しない可能性がありますが、CI クラスの階層を理解しておくことは重要です。CI を手動で追加する必要がある場合に、階層のナビゲーション方法を理解していると、不適切なクラステーブルに CI が追加されないようにすることができます。  

CI クラスマネージャーには CMDB クラス階層全体がツリービュー形式で表示され、クラス定義が一元的な場所にまとめられています。調整ルール、必須フィールドと推奨フィールド、監査テンプレートなど、クラスのメタデータ情報が表示されます。特定のクラスを選択して表示または変更したり、定義を拡張して派生クラスを作成したりすることもできます。クラスごとに、そのクラス用に定義された CMDB 健全性設定、識別および調整ルール、孤立スコアカード、証明書テンプレートに直接アクセスできます。

![[Pasted image 20260624081850.png]]

Basic Info : 表示名、テーブル名、説明、クラスアイコンなど、選択したクラスの詳細が表示されます。  

クラス定義の一部を編集できますが、テーブル名など一部の詳細は編集できません。  

必要なロール : 読み取りには itil、書き込みには itil_admin および personalize_dictionary が必要です。  

Attributes : テーブル属性 (列) が表示されます。属性を編集したり、新しい属性を追加したりできます。  

必要なロール : 読み取りには personalize_dictionary および itil、書き込みには personalize_dictionary および itil_admin が必要です。

## 共通サービスデータモデル (CSDM)

![[Pasted image 20260624082343.png]]

### CS : Common Service (一般的なサービス) 

正確なサービスレベルのレポート作成を実現する、ServiceNow の製品とプラットフォーム全体で共有される標準のサービス関連定義のセット。  

### DM : Data Model (データモデル) 
ServiceNow の製品とプラットフォーム全体にわたる CMDB フレームワーク。複数の構成戦略を実現してサポートします。  

CSDM は、Now Platform 上のすべての ServiceNow 製品で使用される一連の用語と定義です。CSDM 定義は、サービス報告を実現するとともに、CMDB 内でサービスをモデル化するための規範的な指針となります。CSDM を設計図として、使用する IT サービスを ServiceNow にマップすることができます。CSDM フレームワークに従うことで、ServiceNow アプリケーションに必要なデータを適切な CMDB テーブルに正しくマップできます。  

CSDM には次の用途があります。  
- 特定のアクティビティの実行方法を確認する。  
- スコープ内とスコープ外のアクティビティをリストする。  
- ユースケースに関連するテーブルと構成アイテム (CI) の詳細を確認する。  
- ユースケースの利点 (価値提案) を説明する。  
- ライフサイクルの移行を通して資産を追跡する。

## ServiceNow の Discovery と Service Mapping
Discovery* はネットワークをスキャンしてデバイスとアプリケーションの目録を作成し、それぞれ固有のタイプのハードウェアとソフトウェアの結果で CMDB を更新します。  

Service Mapping (トップダウンの検出) は、CI 間の IT の関係性と依存関係で CMDB を補完し、サービスを構成する IT コンポーネントをモデル化します。

![[Pasted image 20260624083050.png]]

### Discovery :  

Discovery では ServiceNow の MID (Management (管理)、Instrumentation (計測)、Discovery (検出)) サーバーが使用されます。これは、データセンターにあるかパブリッククラウドでホストされている顧客の Linux サーバーまたは Windows サーバーで実行できる軽量の Java プロセスです。MID サーバーとは、必要に応じてプロキシーサーバーを通じて通信することもできます。MID サーバーは、デバイスとアプリケーションに関する情報を収集し、結果をインスタンスに戻します。これは Discovery (検出) の段階で行われます。Discovery 製品では、「水平的」な方法でネットワーク上のデバイスが検出されます。  

Discovery は、ネットワーク上のデバイスと、それらのデバイスの重要な属性 (オペレーティングシステム、ソフトウェア、メモリーなど) を検出します。また、アプリケーションとデバイスの間、および相互に通信するアプリケーションの間に関係を確立します。これらの関係は、依存関係ビューアーで視覚化されます。  

一般的に、IT 部門は、デバイスとアプリケーションをスタンドアロンの独立したオブジェクトとして扱うインベントリを作成し、保持しています。デバイスとアプリケーション間の接続は含まれていません。これは通常、水平検出と呼ばれています。この方法では、各オブジェクト間の接続と依存関係を理解するという IT 部門で最大の課題には対応できません。ここで Service Mapping がその役割を担います。  

### Service Mapping :  

アプリケーションサービスとは、組織にサービスを提供するために構成されている、一連の相互接続されたアプリケーションとホストです。アプリケーションサービスには、組織のメールシステムのような社内向けのものと、組織の Web サイトのような顧客向けのものがあります。たとえば、Web ベースのアプリケーションで財務レポートを作成するにはコンピューター、Web サーバー、アプリケーションサーバー、データベース、ミドルウェア、ネットワークインフラストラクチャが必要です。これらのアプリケーションとホストはすべて財務レポートを作成するサービスを提供するために構成されています。  

Service Mapping は、サービスの提供に使用されるデバイスとアプリケーションに基づいて、サービス固有の依存関係をマッピングします。この方法は、トップダウンマッピングと呼ばれます。トップダウンマッピングは、他のアプリケーションサービスオペレーションで問題のあるオブジェクトの影響をすばやく確認するのに役立ちます。このトップダウン方式のアプローチで、サービスマップを既存の構成データにオーバーレイして特定のサービスの基盤となる CI に接続することで、CMDB サービスが対応できるようにします。たとえば、ディスクドライブが失われてデータベースがダウンすると、人事部門が新しい従業員のために機器を注文する際に使用する要求サービスに影響が生じます。  

ServiceNow の Service Mapping は、検出された CI 間に関係性と依存関係を見つけてモデル化し、その情報を自動的に CMDB に入力します。  

ServiceNow の Discovery と Service Mapping の詳細については、ServiceNow 製品ドキュメント  『サービスマッピング』と『ディスカバリー』を参照してください。
