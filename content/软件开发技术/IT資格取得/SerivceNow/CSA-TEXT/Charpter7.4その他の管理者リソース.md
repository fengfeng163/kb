• Instance Scan
• HealthScan
• リリースノート
• Upgrade Center

![[Pasted image 20260628223706.png]]

インスタンスのパフォーマンス監視やインスタンスのメンテナンスアクティビティの実行に役立つ多数のリソースを利用できます。このモジュールでは、これらの機能の認識に役立つ簡単な概要を説明します。これらのトピックに関する情報は膨大なため、自習ボーナスコンテンツが作成されています。時間が許す限り、アクティビティを確認して完了させてください。

## System Diagnostics Stats ツール

**Stats Tools は、パフォーマンス評価のサポートとして、パフォーマンスに影響を与えるクエリー、スクリプト、トランザクションの実行などのシステムアクティビティの統計情報を記録します。**
![[Pasted image 20260628223759.png]]

**メモ**：Stats Tools プラグインはデフォルトで有効になっています。有効化またはアップグレードするには管理者ロールが必要です。com.snc.jrobin も必要です。

Stats Tools は、[System Diagnostics] > [Stats] の下に [Slow Queries]、[Slow Scripts]、[Slow Transactions] などのモジュールを追加します。各モジュールはアクティビティパターンの [sys_query_pattern]、[sys_script_pattern]、[sys_transaction_pattern] のテーブルにアクセスします。

各パターンテーブルは、一意のアクティビティのコレクションを表しています。各コレクションは、期間全体にわたる一意のアクティビティの実行回数を集約したものです。各レコードは、アクティビティの識別可能な詳細を示すとともに基本的なタイミング分析も行います。

**メモ**：デバッグを支援するために、これらのログの大部分をアプリケーションスコープでフィルタリングして、トランザクションを特定のスコープで発生したトランザクション (遅いスクリプトやイベントなど) のみに制限できます。

アクティビティパターンは即座にキャッシュに記録され、後でパターンテーブルに保持されます。サーバーキャッシュをフラッシュすると、保持されていない記録済みのアクティビティがクリアされます。パターンレコードの例を以下に示します。

- 記録および永続性のしきい値を満たすクエリーが実行されるたびに、そのクエリーが集約され、クエリーのパターンレコードとして保存される。
- 特定のビジネスルールが実行されるたびに、スクリプトのパターンレコードに集約される。
- 特定のバックグラウンドジョブが実行されるたびに、一意のトランザクションパターンレコードに集約される。
- [Incidents] リストの [New] ボタンをクリックするたびに、特定のフォームアクションによってリストタイプのトランザクションパターンとしてカウントされる。

## Automated Test Framework
![[Pasted image 20260628224048.png]]

**メモ**:本番システムで自動テストが誤って実行されるのを防ぐために、デフォルトでは自動テストを実行するためのシステムプロパティが無効になっています。データ破損や機能停止を回避するために、テストは開発インスタンス、テストインスタンス、その他の非本番インスタンスでのみ実行してください。

テストには、実行時にテストで試行される一連のステップが含まれます。テストを実行すると、Automated Test Framework により Test Results レコードが作成れます。 このレコードは、テストレコ一ドの関連リストに表示されます。

また、すべてのテストレコードはテストステップ(個々のステップと、テストで実行されるときの順序)によって定義されます。1つのテストステップには、アクションが1つと、そのアクションを実行するのに必要なデータが組み込まれています。ATFは、ほとんどのユースケースに対応するステップ構成のデフォルトリストを提供しています。また、テスト設計者は独自のカスタムステップ構成を作成できます。

テストにフォームまたは他のユーザーインターフェイス要素が関係するステップが合まれている場合、そのテストでは、オンデマンドまたはスケジュールした設定時刻に、ブラウザのタブまたはウインドウでステップが実行されます。テストの実行状況をリアルタイムで確認するには、ブラウザでテストを実行する方法が特に有効です。

Automated Test Framework は、変更マネ一ジャーや開発者に次のようなメリットをもたら します。
- 手動でのテストを自動テストに置き換えることで、アップグレードや開発の時間を短縮します。
- テストを設計すると、それを別のコンテキストや別のテストデータセットで再利用できます。
- テストデータと各テストの実行後に行われた変更をロールバックすることで、テストインスタンスをクリ一ンに保てます。
- テストスイートを作成して、テストをバッチで整理して実行できます。
- テストスイートの実行をスケジュ一ルできます。
- 専門的な技術のないテスト設計者が標準的な ServiceNow プラットフォーム機能のテストを作成できます。
- クイックスタートテストやテストスイートをコピーすることによって、テストの設計時間を短縮します。
- カスタムテストステップを作成して、テスト範囲を拡大できます。

Automated Test Framework の詳細については、ServiceNow ドキュメント『Automated Test Framework』を参照してください。

## App Engine Studio (AES)

- 作成済みアプリケーションの表示と検索
- 開発を始めるためのチュートリアルと役立つリソースの確認
- アプリへのデータ、エクスペリエンス、ロジック、セキュリティの追加
![[Pasted image 20260628224405.png]]

ローコード開発に App Engine Studio を使用すると、ビジネスプロセスの自動化やビジネス問題の解決が可能になります。AES では、これまで管理者にアサインされていた開発作業をほぼトレーニングなしで委任できます。その結果、管理者は、プラットフォームでより戦略的かつ幅広い問題に取り組めるようになります。

App Engine Studio では、開発ツールを活用し、事前構築されたソリューションのテンプレートを使用してアプリをすばやく構築できます。この直感的なアプリ開発環境で、リアルタイムデータを活用し、組織内の従業員を支援します。

AES を使用して、以下も実行できます。　  
- アプリケーションをスクラッチで作成できます。  
- 構築した最新アプリケーションのリストにアクセスできます。  
- オブジェクトをアプリに追加する、アプリのテンプレートを参照する、利用可能なツールの詳細を確認するためのリンクにアクセスできます。  
- データ、エクスペリエンス、自動化、セキュリティが事前に設定された、アプリの作成に使用できるテンプレートのリストを参照できます。  

メモ：企業のライセンスに応じて、App Engine を別途購入しなければならないことがあります。

## 委任開発者

**委任開発者は、アプリケーションを開発するための権限を 1 つ以上アサインされている、管理者以外のユーザーやグループです。**

**各権限により、admin ロールなしでシステムの制御権を保持するための、委任開発固有のロールが 1 つ以上付与されます。**

![[Pasted image 20260628224653.png]]

委任開発者には、デプロイ権限に加えて次の権限を付与できます。  
- All File Types : 他のオプションでは付与されないものを含め、すべてのアプリケーションファイルタイプへのアクセス権が開発者に付与されます。  
- Integrations : Web サービス API、REST API、およびデータソースへのアクセス権が開発者に付与されます。  
- Reporting : レポートおよびレポートスケジュールへのアクセス権が開発者に付与されます。  
- Workflow : ワークフローエディターとアクティビティクリエーターへのアクセス権が開発者に付与されます。  
- Service Catalog : カタログアイテム、レコードプロデューサー、変数などカタログに関連したファイルタイプへのアクセス権が開発者に付与されます。  
- Service Portal : サービスポータルのエディターとツールへのアクセス権が開発者に付与されます。  
- Flow Designer : フローおよびアクションを作成するための Flow Designer 設計環境へのアクセス権が開発者に付与されます。スクリプトアクションのステップでは、Allow Scripting 権限が必要です。  
- Tables & Forms : テーブル列、フォームレイアウト、リストレイアウトなどのモデルとレイアウトに関連したファイルタイプへのアクセス権が開発者に付与されます。  
- Manage ACLs & Roles : アクセス制御やユーザーロールなどのセキュリティ関連のファイルタイプへのアクセス権が開発者に付与されます。  
- Allow Scripting : ビジネスルール、クライアントスクリプト、Flow Designer のスクリプトアクションステップなどでのスクリプトフィールドへの書き込みアクセス権が開発者に付与されます。  

 詳細については、ServiceNow 製品ドキュメント『Delegated Development と展開』を参照してください。    
  
 developer.servicenow.com は、開発者だけでなく、ServiceNow 内のアプリケーションの開発に興味のあるすべての人にとって優れたリソースです。

## アップグレードとリリース
![[Pasted image 20260628224927.png]]
**インスタンスのアップグレードには、計画、テスト、検証が必要です。リリースノートでは、アップグレードを成功させるためのフェーズとタスクを完了する方法が説明されています。**

ServiceNow プラットフォームには、アップグレード中およびアップグレード後に役立つツールが用意されています。ServiceNow のアップグレード、アップグレード前後のタスク、アップグレード計画のチェックリスト、アップグレードのツールとリソース、および ServiceNow ストアを調べてみてください。アップグレードをさらに快適にするために独自のリリースノートを作成することもできます。独自のリリースノートには、製品情報、対象のリリースバージョンに含まれている修正、アップグレードの準備を効率化するためのアップグレードタスク (ファミリリリースをスキップする場合も含む) などを盛り込むことができます。

作業を開始するには、ServiceNow 製品ドキュメント (docs.servicenow.com) にアクセスし、「Release notes and upgrades」セクションを確認してください。

リリースノートの使用に関するビデオチュートリアルは、次の場所で視聴できます。Product Documentation | Using the release notes

## アップグレードとアップデート
![[Pasted image 20260628225021.png]]
**実行中のリリース** :
システム管理者は stats.do を使用して、インスタンスでどのリリースが実行されているのかを確認することができます。

サポート対象リリース :
サポート対象リリースのバージョンは、最も新しい 2 つのリリースのうちのいずれかです。サポート対象バージョンには、24 時間年中無休で技術支援を提供しており、パッチとホットフィックスを利用できます。
使用中のリリースを確認するには、アプリケーションフィルターで「stats.do」と入力し、Enter/Return キーを押してインスタンスの統計情報を表示します。

実行中のリリースをチェックするには、次のようにします。
• ビルド名、ビルドの日付、ビルドタグを見つける。
• ビルド名をリリースノートのリリース名と照合する。
• ビルドの日付およびタグを、リリースノート内のビルドの日付およびタグと照合する。

アップグレードとパッチの確認 :
system.upgraded イベントは「System Upgraded (システムがアップグレードされました)」という通知をトリガーできます。イベントがエラー状態になっても通知は送信されません。ただし、アップグレードは正常に完了することがあります。

アップグレードが完了したことを確認するには、次のようにします。
• [All] > [System Diagnostics] > [Upgrade Log] に移動します。
• 「Notifying HI that upgrade has been completed. (アップグレードが完了したことを HI に通知)」というメッセージを見つけます。

パッチが適用されたことを確認するには、system.patched イベントを見つけます。デフォルトでは提供されていませんが、このイベントの通知を作成できます。
