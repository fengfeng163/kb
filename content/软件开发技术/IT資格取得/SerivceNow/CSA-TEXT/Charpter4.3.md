インポートセットは、ServiceNow にデータを取り込む仕組みを提供します。インポートセットは、インポートセットテーブルにデータを格納します。admin または import_admin ロールを使用してログインしたユーザーは、インポートセットのあらゆる側面を管理できます。  

**データソース**は、インポートセットのデータソースに関する情報を含む、ServiceNow のレコードです。ローカルソースのデータ (XML、CSV、Excel など) をインポートしたり、パスおよび認証情報を指定することによってネットワークサーバーからインポートしたりできます。ファイル、LDAP (Lightweight Directory Access Protocol) 接続、または JDBC (Java Database Connectivity) 接続をデータソースとして使用できます。  

**インポートセットテーブル**は、データソースからインポートされたレコードのステージング領域として機能します。  変換マップは、インポートセット (ステージング) テーブルから「ターゲット」テーブルにデータを移動するための指針となります。フィールドマッピングにより、フィールド間でデータが直接移動されます。  

**変換マップ**は、インポートセット内のフィールドと既存の ServiceNow テーブル (インシデントやユーザーなど) 内のフィールド間の関係性を決める一連のフィールドマップです。定義済みの既存の変換マップは、インポートセットから ServiceNow テーブルへのデータのマッピングに再利用できます。管理者は、Transform Map モジュールを使用して、インポートされたデータの ServiceNow テーブル上の格納先を定義します。変換マップの設定では、インポートセットテーブルのソースフィールドと任意の ServiceNow テーブルの格納先フィールド間のリンクをドラッグアンドドロップのような簡単な操作で指定できます。 

**ターゲットテーブル**は、変換後のデータを配置する既存のテーブルです。

データをインポートする前に、取り込むデータの内容とそのデータを格納する場所を把握することが重要です。  

インポートする前にデータを検証する必要があります。適切でないデータは、インポートおよび変換のプロセスで問題を招く可能性があります。インポート前にデータの計画と検証に時間を費やすことで、後々の時間を節約し、潜在的な問題を削減できます。  

注意すべきポイントは次のとおりです。  
- データを非常に大きなかたまりでインポートしないようにしてください。  
- 非常に大きいインポートセットを作成すると、広範囲にわたる遅延の原因になります。  
- インポートされたファイルのラベルは、データがロードされるインポートセットテーブルの名前の決定に使用されます。  
- インポートはスケジュールすることも可能です。  

**メモ**：既存のインポートセットテーブルを選択して、同じソースのデータのロード、または格納先のフィールド/列が同じであるデータのロードに使用することもできます。   

データインポートのスケジュールの詳細については、ServiceNow 製品ドキュメント『データインポートのスケジュール』を参照してください。

## 変換マップ
![[Pasted image 20260623232533.png]]
変換マップは、インポートセット内のフィールドと既存の ServiceNow テーブル内 (Incident [incident] や Users [sys_user] など) のフィールド間の関係性を決める一連のフィールドマップです。  

変換マップには柔軟性があります。仕様がシンプルで、アプリケーションによってソースと格納先のフィールド名を自動的に一致させることができます。また、マッピングに詳細ロジックを使用したり、ServiceNow のスクリプティング環境のすべての機能を活用したりできます。単一のインポートセットフィールドを、ターゲットテーブルの複数フィールドにマッピングすることもできます。任意のテーブルをインポートセットの変換結果の格納先として使用でき、テーブル内の任意のフィールドを、インポートセット内のフィールドを変換した結果の格納先として使用できます。  

変換したデータを配置する ServiceNow テーブル (ターゲット) を選択します。選択できるテーブルは、現在選択されているアプリケーションのスコープ内にあるもの、グローバルスコープ内にあるもの、または他のアプリケーションに書き込みアクセスを許可しているものです。名前およびソーステーブルは、インポートセットにアサインされたラベルに基づいて設定されます。データを転送できるターゲットテーブルをアサインする必要があります。  

**自動マッピングユーティリティ** : インポートセットのすべてのフィールド名が、データを変換するターゲットテーブルのフィールド名と一致する場合、マッピング方法は最も簡単になります。この場合、[Table Transform Maps] フォームの関連リンクにある [Auto Map Matching Fields] をクリックして、一致が適切か確認するだけです。  

**マッピング支援ユーティリティ** : マッピング支援ユーティリティでは、視覚的に直感的な環境を使用して、インポートセットフィールドとターゲットテーブルフィールドの間のマッピングを指定できます。マッピング支援ユーティリティを使用すると、単一のソースフィールド (Import Set テーブルのフィールド) を複数の格納先フィールド (ターゲットテーブルのフィールド) にマッピングできます。フィールドの自動一致の結果に不一致がある場合は、マッピング支援ユーティリティを使用して簡単に修正できます。すべてのフィールドが適切に一致した場合、関連リンクの [Transform] をクリックして、格納先テーブルへのデータ変換を開始します。


## 結合（Coalesce）フィールド
単体フィールド (または複数フィールド) を結合すると、インポート時にそのフィールドが一意のキーとして使用されます。
![[Pasted image 20260623232904.png]]

結合を使用する理由は、結合が定義されていない場合、インポートされたすべての行が新しいレコードとして扱われるためです。既存のレコードは更新されません。もう一度インポートを実行した場合、重複レコードが作成されます。  

ターゲットフィールドを結合するように設定すると、インポートセットがフィールドを一意のキーとして扱うようになります。選択した場合、インポートセットアプリケーションは、レコードに対するソース値と既存のレコードからの値のマッチングを試みます。一致が見つかった場合、変換マップは、新しいレコードを作成するのではなくレコードを更新します。一致が見つからなかった場合、インポートセットアプリケーションでは必ず、変換ごとに新しいレコードを作成します。  

**シナリオ** : 人事部門から 200 件のレコードを含む Excel スプレッドシートが提供され、そのレコードをテーブルにインポートするとします。初回は、データが一意の場合はインポートが機能します。しかし、1 か月後、人事部門は同じスプレッドシート (元は 200 件のレコード) に 300 件のレコードを追加し、合計 500 件のレコードを手にして戻ってきました。200 件のレコードは 1 か月前にインポートしたため、すでにテーブル内に存在するということを頭に入れておいてください。結合を選択しなければ、スプレッドシートには 500 件ではなく 700 件のレコードが存在することになりします。その理由は、結合しなければ、インポートしたすべてのレコードが新しいレコードとして扱われるためです。  

インポートセットのデータの結合に使用できる構成がいくつかあります。  

- 単一フィールド結合 : 単一のフィールドで結合を行い、既存のレコードを更新できます。ターゲットテーブルのレコードに、結合フィールドの値がインポート (ステージング) テーブルのレコードと同じであるものが存在する場合、ターゲットテーブルのレコードは、インポートセットレコードの値を使用して追加されるのではなく、更新されます。  
- 複数フィールド結合 : 複数のフィールドで結合を行い、既存のレコードを更新できます。ターゲットテーブルレコードが持つすべての結合フィールドの値がインポート (ステージング) テーブルレコードのそれらの値と同じ場合、インポート (ステージング) テーブルのレコード値でターゲットテーブルレコードが更新されます。複数のフィールドの結合を行うには、ターゲットテーブルとインポート (ステージング) テーブルの間ですべての結合フィールド値が一致する必要があります。  
- 条件付き結合 : スクリプトを使用して、インポート (ステージング) テーブルの行をターゲットレコードに結合する必要があるかどうかを決定できます。ほとんどの条件付き結合スクリプトは、sys_id フィールドのフィールドマップの [Source script] フィールドで定義します。インポート (ステージング) テーブルのレコード値を使用してターゲットレコードを更新するには、スクリプトがターゲットテーブルレコードの sys_id を返す必要があります。
