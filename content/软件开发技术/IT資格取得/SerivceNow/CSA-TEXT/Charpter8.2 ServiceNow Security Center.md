## ユーザーストーリー
管理者として、ServiceNow Security Center を簡単に操作し、Now Platform のセキュリティとコンプライアンスを向上させたいと考えています。インスタンス全体でセキュリティ関連のアクションと動作を監視する必要があります。

## Security Center
![[Pasted image 20260629080836.png]]
ServiceNow Security Center は、システム管理者がインスタンスのセキュリティを管理、監視、改善するのに役立つ、組み込みアプリケーションです。セキュリティ関連の専用ツールセットを統合し、最高レベルのセキュリティ監視とセキュリティ設定を維持する管理者の作業をサポートします。 

Security Center にアクセスするには、[All] > [Security Center] > [Admin] > [Security Center] の順に選択します。    

Security Center にログインすると、ホームページが表示されます。ホームページは、Security Center アプリケーションのさまざまなパートにおける現在の場所を表すダッシュボードです。ホームページから各種レポートを表示することができます。 

Security Center を使用するには、admin ロールまたは sn_vsc.security_center_viewer ロールが必要です。

ホームページを確認すると、インスタンスのセキュリティ確保に役立つ、Security Center のいくつかの機能と特徴があります。
- 強化 
- スキャナー 
- 顧客アクション  
- ベストプラクティス  
- 通知  
- Learning 
- 測定基準

## Security Center : 概要
![[Pasted image 20260629081003.png]]

[Overview] ページには、それぞれのセキュリティスキャンの結果数を時系列で示した要約セクションとチャートが表示されます。[Hardening compliance score summary] (顧客のセキュリティ設定が、推奨される設定とどのくらい適合しているかを示す %) にアクセスするか、[All] > [Hardening] > [Score Trend] を順に選択します。

## Hardening
![[Pasted image 20260629081032.png]]

[Hardening] セクションには、ServiceNow が推奨する設定に対して顧客インスタンスのセキュリティプロパティがどのくらい準拠しているかが示されます。既存のハードニング設定では、ServiceNow の推奨事項に準拠していることが保証されています。 

このセクションでは、ハードニングスコア、優先度ごとの影響、セキュリティ分野ごとの影響を確認できます。[Hardening Settings] を変更する場合は、直接ドリルダウンして変更できます。時系列での傾向も確認できます。[Score Trends] タブには、現在の状況を確認するための情報が時系列で表示されます。フィルターの作成、KPI シグナルの特定、目標としきい値の設定をすることもできます。    

## Scanner
![[Pasted image 20260629081108.png]]
Scanner 機能は、設定ミス、過剰なアクセス制御、その他の安全でない動作についてセキュリティチェックするために、顧客のインスタンスをスキャンします。Scanner 機能にアクセスするには、画面上部のバナーで [Scanner] をクリックします。 

このセクションでは、Security Scan Comparison について確認します。これは、現在設定されているセキュリティスイートを示しています。セキュリティチェックのカスタムスイートを実行および作成することができます。新しいスイートを設定するには、画面の左側で [Suites] をクリックし、[New] をクリックします。スイートのタイトルと説明を入力します。[Checks] セクションで、実行するチェックの内容と構成を選択します。   

セキュリティスイートを実行した後、[Scan Finding] タブで結果を確認できます。 

## 顧客アクション
![[Pasted image 20260629081143.png]]

顧客アクションは、プラットフォーム上で注意を必要とする可能性のあるものに対処するためのサポートです。たとえば、Password2 フィールドにおける 3DES の廃止などです。これは、現在使用しており、削除が必要なものや、設定していないものである可能性もあります。Security Center は、不要なものや、リスクをもたらす可能性のあるものを変更する手順を案内します。 

顧客アクションにアクセスするには、上部のバナーで [Customer Actions ] を選択します。顧客アクションで注意が必要なものの件数とグラフを確認します。ページの下半分に示されている、特定のアクションに注意してください。特定されたテクノロジーをどのように使用しているかによって、対処が必要な場合があります。 

ServiceNow のセキュリティチームまたは管理チームと協力して、どのように対応するか、および対応が必要かどうかを判断する必要があります。特定されたいずれかのアクションを選択すると、完了すべき手順と、従うべきワークフローが表示されます。  

## ベストプラクティス
![[Pasted image 20260629081228.png]]
ベストプラクティスは、最初のセキュリティ設定を行う際の出発点になります。ベストプラクティスでは、インスタンスの基本的なセキュリティニーズの一部を設定できます。

ベストプラクティスを利用するには、上部のバナーで [ Best Practices ] を選択します。設定が完了したウィジェットの数、ServiceNow のジャーニーで完了したステップの棒グラフ、基本構築用のフィルター、ベストプラクティスの設定が、ページの下半分に表示されます。下半分のいずれかの設定をクリックすると、対象の設定に移動し、変更を行うことができます。各設定では、[Task Steps] を選択して独自のステップにアクセスできます。 

ステップのタイトル (太字) を選択すると、そのステップを完了するための具体的な説明が表示されます。 複数のタスクが必要なものもあります。その場合、タスクステップは分割して示され、左側にステップのリスト、右側に太字のタイトルが表示され、展開するとステップが表示されます。ベストプラクティスが完了していることを確認するには、すべてのタスクステップを完了する必要があります。

## Notifications
![[Pasted image 20260629081321.png]]
Notifications では、しきい値によってトリガーされるアラート通知の「ポリシー」を設定し、ステークホルダーに変更を通知することができます。Notifications にアクセスするには、上部のバナーで [Notifications] を選択します。既存のポリシーを使用することも、Security Center によって特定されたイベントを通知する独自のポリシーを作成することもできます。

[Custom Policy] をクリックするか作成して [Policy Settings] に移動すると、トリガーイベントが発生するタイミング、適用する条件ロジック、通知をトリガーするロール、通知が基づいている内容、通知を受信するグループと個人を設定することができます。 

## Learning
![[Pasted image 20260629081404.png]]
[Learning] セクションには、セキュリティジャーニーをサポートするために一般的に使用されるセキュリティリソースへのリンクが含まれています。[Learning] に移動して、セキュリティに関するホワイトペーパー、電子書籍、ナレッジベース (KB) の記事、製品ドキュメント、コミュニティのディスカッションを、統合された 1 つのビューでご確認ください。コンテンツはヘッダーと UI カードで整理されているため、適切なリソースをすばやく見つけることができます。

## 測定基準
![[Pasted image 20260629081451.png]]
[Metrics] セクションでは、セキュリティに関するさまざまな重要業績評価指標 (KPI) や、リスクの高い行動を監視・分析して、セキュリティ侵害を回避することができます。Metrics にアクセスするには、上部のバナーで [Metrics] を選択します。 

デフォルトのダッシュボードを使用することも、独自のダッシュボードを作成することもできます。ウィジェットを使用するように設定することも可能です。[Metrics] セクションで、特定のレポートを詳しく調べて、すべてのレコードを確認することもできます。たとえば、ログインの失敗回数が急増した場合は、ハッキングを試している可能性があります。また、それぞれの設定の測定基準を追跡することもできます。設定内で生じている機能に基づいて通知を送信するしきい値を設定することができます。 

## Security Center の導入 : 進捗の管理
![[Pasted image 20260629081524.png]]
セキュリティに対して、常に注意していることが必要です。最初に、ServiceNow 管理者とセキュリティチームで定期的にミーティングをすることが推奨されます。 

Security Center をレビューする頻度として、最初の設定後、最低でも四半期に 1 回は実施し、毎月ミーティングを行い、不明点を評価することが推奨されます。 

 セキュリティチームと ServiceNow チームで時間をとって、未解決の設定 (注意を必要とする可能性があるもの、または組織に適用できないと判断されたもの) について話し合いが必要になるかもしれません。これらのミーティングでは、チームで疑問をもった設定について詳細なメモをとることが重要です。 
 
これらのレビューミーティングでは、質問への回答やソリューションの実施をサポートするために、アカウントチーム、ServiceNow Security チーム、ServiceNow パートナーを含める必要があるかもしれません。設定に変更があった場合は、インスタンスのセキュリティを維持するために、できるだけ早くこれらの更新を行う必要があります。アップデートやパッチを適用する前に、準本番環境におけるユーザー受け入れテストで機能的な影響をテストする必要があります。 

## コンプライアンススコアの改善方法
![[Pasted image 20260629081558.png]]

前述のとおり、コンプライアンススコアは ServiceNow のセキュリティ強化努力と直接相関しており、このスコアは 1 ～ 100 % の整数で示されます。変更が行われるたびにスコアが更新されます。これは、各設定に 0 ～ 1 の影響スコアが関連付けられているためです。 

組織にはそれぞれ独自のコンプライアンス要件があるため、独自のコンプライアンス目標スコアがあります。組織は、セキュリティチームおよび管理チームと包括的なレビューを行い、インスタンスに適用する設定を決める必要があります。セキュリティの専門家は、各設定の強化内容と関連するリスクを理解し、管理者チームは機能的な影響を理解します。必要に応じて評価および実装すべき設定の全体像を形成するには、両方の要素を組み合わせる必要があります。

改善できそうな箇所を特定するには、[Hardening] セクションから始めてください。コンプライアンスに準拠していない設定のうち、[Critical] と [High] のものから確認します。項目を変更するには、左側のタブの [All Settings] に進むか、リストから直接 [Hardening Setting] をクリックします。コンプライアンススコアは、ServiceNow のセキュリティチームと協議する Security Center の Cadence ミーティング、信頼できるパートナーとのドキュメンテーションおよびトレーニングで使用できて、ServiceNow インスタンスのセキュリティについて最適な方向性を設定するのに役立ちます。 

## Security Center アプリケーションに対するパッチ適用とアップグレード
![[Pasted image 20260629081636.png]]

Security Center アプリケーションのアップデートは、ファミリーリリースに加えて年に 2 回リリースされます。Security Center をアップデートする前に、目的のファミリの準本番環境で、環境を十分にテストしてください。同じ準本番環境で Security Center を導入してテストします。準本番環境でのテストがすべて完了すると、[Filter Navigator] > [All Available Applications] > [All] > [Search for Security Center] と選択して、Security Center に対するアップデートを確認できます。 

アプリケーションを同期して、アップデートが有効になっているかどうか確認します。アップデートが有効になっている場合は、アップデートをインストールします。アップデートが完了したらブラウザを更新して、追加された可能性のある新機能について、時間をとって学習してください。
