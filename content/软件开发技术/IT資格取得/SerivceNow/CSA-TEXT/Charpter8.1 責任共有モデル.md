## 責任共有モデル
![[Pasted image 20260629080116.png]]

ServiceNow の責任共有モデルは、顧客、ServiceNow、およびコロケーションプロバイダー間のセキュリティに関する責任を定義するものです。ServiceNow Security Center は、Now Platform に追加費用なしで含まれるアプリケーションで、顧客側の管理者がセキュリティ上の責任を遂行し、ServiceNow インスタンスのセキュリティを管理・監視するのをサポートします。

セキュリティ全体の責任は、顧客、ServiceNow、コロケーションプロバイダーの間で分担されます。ServiceNow は顧客にさまざまな機能を提供して、自社のセキュリティポリシーや要件を満たすようなインスタンスを構成できるようにしています。 

責任共有モデルの一環として、顧客はデータの収集、保存、利用、共有、保管、破棄の方法を決定する責任を負います。また、顧客は自社のデータの正確性と機密性を維持する責任も負っています。次に、顧客が維持に対して責任を負う主な項目について説明します。 

## 暗号化
![[Pasted image 20260629080238.png]]


**保管中** :
顧客は暗号化の要件を定義してマッピングし、ServiceNow が提供する最適なソリューションサービスと適合させる必要があります。保管中のデータ暗号化オプションには、アプリケーションセントリックなカラムベースの暗号化、およびフルバックエンドのボリュームベースの暗号化が含まれています。

**送信中** :
ServiceNow は、デフォルトで TLS (TLS 1.2 以上) セッションを使用して送信中のデータを暗号化し、顧客データを保護しています。Now Platform インスタンスのメールで送信または受信されるメールで opportunistic (日和見) TLS がサポートされるようになりました。顧客のメールシステムで TLS 暗号化をサポートするように設定されている場合、SMTP ハンドシェイク中にネゴシエーションが行われます。 

## 暗号化キーの管理
![[Pasted image 20260629080333.png]]
Now Platform の Key Management Framework (KMF) により、顧客は顧客インスタンス上で暗号化操作がどのように行われるかを管理することができます。顧客は、暗号化の管理と運用、監査、統合に対して専任の役割を割り当てることで、職務を分離する責任があります。顧客が Cloud Encryption (CE) または Column Level Encryption Enterprise (CLEE) に対して顧客提供のキーを使用することを選択した場合は、顧客自身でキーを生成し、顧客のインスタンスに転送する責任があります。

注 : CE および CLEE は有料のソリューションです。

## ログ記録と監視
![[Pasted image 20260629080412.png]]
ServiceNow プラットフォームにおけるログ記録は、次の 2 つのレベルで行われます。
### ServiceNow
1.**インフラストラクチャログ** : インフラストラクチャログは、ServiceNow のサポートで使用されるネットワークおよびサーバーのデバイスが含まれている環境から収集されます。これらのログは ServiceNow の SIEM システムに提供されます。このシステムで取得されたログファイルは、顧客が参照することはできません。これらのログファイルは、環境を監視して、異常な動作を検出するために使用されます。S

erviceNow は 90 日間ログを保持しますが、容量が多く価値が急速に失われるログの保持期間は 90 日より短くなることがあります。これらのログファイルにアクセスできるのはセキュリティスタッフだけです。
### 顧客
2.**アプリケーションログ** : アプリケーションログはアプリケーションから情報を収集します。これらの情報は個々のインスタンスに個別のものです。顧客は、アプリケーションログファイルに対して完全なアクセス権を持ち、アプリケーションからこれらのログファイルをダウンロードできます。最も詳細なログはトランザクションログで、これはシステム内でクリック、表示、またはアクションが発生するたびに取得されます。顧客は、自社のインスタンス内の広範なセキュリティ関連のログに対してアクセス権限を持っており、不審な動きがないか定期的かつ継続的にログを監視する必要があります。

顧客は、以下のようなセキュリティ関連情報に対してアクセス権限を持っています。
• 顧客のエンドユーザーアクティビティ
• ログイン試行の失敗
• 監査証跡とレコード履歴
• 管理のエスカレーション
• ServiceNow のサポート担当者によるアクセス

## 脆弱性管理
![[Pasted image 20260629080611.png]]
顧客は ServiceNow のパッチ適用プログラムにより、年間を通じて必須または推奨のパッチバージョンにインスタンスを更新することができます。ServiceNow は毎月パッチ適用プログラムを実施し、顧客がパッチを適用できるようにしています。アプリケーションの開発中の脆弱性管理についても、確立された手順があります。顧客は、ニーズとコンプライアンスの要件に最も適した、自身のインスタンスに対するパッチ適用とアップグレードのスケジュールを管理する責任があります。

ServiceNow は Now Platform を年 2 回リリースしています。また、メジャーリリースのサポート期間中にパッチとホットフィックスが作成され、次のバージョンに含めるためにコードベースに組み込まれます。  

## セキュリティ担当者の管理
![[Pasted image 20260629080652.png]]
ServiceNow は、主に Now Support Portal のアカウントに記載されている指定のセキュリティ担当者を通じて、顧客とやりとりします。指定のセキュリティ担当者は、ServiceNow Security Office からセキュリティ関連の情報を、通常はメールで定期的に受け取ります。 

セキュリティについて懸念があり、ServiceNow が緊急に連絡する必要がある場合、常に正しいセキュリティ担当者がすぐに連絡できる状態であることが重要です。管理者がこのフィールドを更新する方法については、こちらをご確認ください。 

指定のセキュリティ担当者は、機密なセキュリティ問題に対応する権限を持ち、常に連絡を取れる状態にしておくことが必要です。したがって、この要件を満たすために、メールの配信リストと個人の両方を登録しておくことを強くお勧めします。

これらの連絡先情報は、この目的でのみ使用され、**それ以外には使用されません**。この連絡先情報は必ず最新の状態にしておいてください。 

顧客がプラットフォームの安全を確保できるように、ServiceNow は ServiceNow Security Center を開発しました。Security Center は、プラットフォームのさまざまな設定をサポートし、データ管理者の責任となっている設定の維持・管理の負担を軽減します。
