## Debugging: GlideSystem logging methods
![[Pasted image 20260813224335.png]]
Use the System Logs > System Log modules to view messages logged by the gs.info(), gs.error(), gs.warn() , gs.debug(), and gs.log() methods. Since gs.info() can be used with Scoped Applications and in the Global Scope use it instead of the legacy method gs.log().

The gs.addInfoMessage() and gs.addErrorMessage() methods are helpful debugging strategies during class, because the feedback is immediate. This strategy can be less effective in an environment with multiple administrators as they can see your messages at the top of the form.

>**Tip from the Field**: The default source for the gs.info() methods is Script. To use a different source, pass an optional source parameter to the method. Then save a query locating all the records in your source as a favorite.
Example:
gs.info(“The value of State: ” + current.state);

>Important: Keep in mind that, info, error, warn, and debug logging methods are not only intended for Scoped Applications but can also be used in the Global Scope. However, these logging methods provide verbosity levels to a log message. Another consideration is that gs.log() cannot be used if you are developing in a scoped application.

## Debugging: Script Debugger
Used for debugging server-side JavaScript.
• Opens in a separate browser window along with Script Tracer and the Session Log.
![[Pasted image 20260813225458.png]]

The Script Debugger offers:
- The ability to step through your script line-by-line.
- Set and remove breakpoints.
- Pause a script at a breakpoint.
- Step into and out of function and method calls.
- View the value of local and global variables in real time.
- View the value of private variables from function closures.
- View the call stack.
- View the transaction the system is processing.

Opens in a new browser window

Requires the script_debugger or the admin role

The Script Debugger can also be launched in the Studio by selecting File > Script Debugger.
